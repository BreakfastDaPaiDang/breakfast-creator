# 文案创作流程

AGENTS.md 的授权边界优先于本文。文风见 `brand/voice.md`。2026-10 首个完整项目《广告不是画报，机主不是资产》按协作模式跑通，本文据此修订。

## 两种模式

| | 协作模式（半自主） | 全自主模式 |
|---|---|---|
| 用户给什么 | 核心议题、切入点，之后每一轮的反馈和删改 | 核心议题和独特切入点，可附偏好；开工时说明“全自主” |
| 谁做决定 | 每个阶段的方向由用户确认；正文 Agent 做加法、用户做减法 | Agent 自己决定、自己删改，决定记入 `decisions.md` |
| 停下来问用户 | 每轮交付后 | 只在下文“停止条件”出现时 |
| 交付 | 各阶段文件，终稿 `script.md` | 同左，外加 `decisions.md` 和一份收尾说明 |

两种模式走同一套阶段、同一套质量标准，区别只在谁来把关。

## 一、阶段

默认顺序：初步议题与切入点 → 竞品与背景扫描 → 第一轮两份报告 → 最终项目决策 → 视频项目简报 → 专项研究与《研究资料整合报告》 → 大纲 → 开场打磨 → 逐章写作 → 整体润色 → 机械检查 → 终稿。协作模式在每个箭头处等用户确认；全自主模式自己过关卡。

### 第一轮：扫描与两份报告

- 每个项目由用户给出本期核心议题和切入点，账号长期人设和立场不能替代本期构想。Agent 自行安排对标与事件检索、候选筛选、正文和评论阅读，不把搜索词、链接整理或工具配置转交给用户。
- 交付《竞品文案分析报告及我们的切入点选择》和《评论区舆情分析与“金句”提取报告》。前者提炼对方具体的观点、论据、可借鉴与可深化之处，并推荐我们的方向，叙事结构分析作辅助；后者回答实际存在的立场、情绪、争议、变化及原因、诉求，保留重要反对意见。
- 事件选题先搜事件名、涉事产品／机构及事件后续，再扩展到同类现象；工具联调的宽泛样本不能当作主要研究材料。平台候选先看事件相关性与发布时间，再参考回答量、浏览量等数据；不把热度当作观点质量。
- 评论由工具采集和初筛，Agent 阅读、挑选。金句报告以评论为主，同时收对标文案原句，标明两类来源。精选评论按完整单条呈现，不节选、不改写，附点赞数和来源。
- 报告结论直接，证据可回查；删套话、重复背景、逐条泛泛解读和无必要的边界说明，采集细节集中放资料索引；同一信息不在两份报告反复铺陈。

### 第二轮：项目决策与简报

- 先提出“最终项目决策”：核心议题、核心论点、独特切入点、预期风格／调性。确认后写 `brief.md`，四部分：①核心方向；②内容与知识框架（事件、案例、人物、现象；理论、概念、学说和历史背景）；③幽默与金句储备（笑点方向、候选金句、评论区和对标原句，完整单条，附编号、赞数和可接的论证位置）；④后续研究任务，至少三个方向，各列要回答的问题、查找的材料和预期交付。
- 幽默与金句储备在研究和写作中持续补充。简报记录最新决策，优先于前轮报告中的旧建议。

### 第三轮：专项研究与资料整合

- 事实与商业研究、社科与批判研究都要服务核心议题：查清收入、规则和利益分配，也要解释支配关系如何形成、被接受并持续运转，以及其中的矛盾。
- 理论研究进入相关的当代讨论和前沿争论，结合必要的经典原文。比较两到三种有实质差异的解释，说明各自揭示什么、遗漏什么，再选能贯穿本题的机制叙事；不先定结论再找理论装饰，不以术语新、作者多代替解释力，不把某个项目的理论固定为所有选题的框架。
- 优先读学者原文、代表性章节及论争回应，不把摘要、书评或下载完成当作读完。区分作者论点与 Agent 的应用；实际阅读范围和获取缺口记入资料索引。
- 机制叙事连接制度与技术安排、经营目的、人的行动及关系的再生产，解释便利、自由选择、抵抗与支配为何共存；不靠加强攻击性或添加弱者故事补足理论。用具体材料检验、修正解释，允许研究改变原先的问题和核心论点。
- 《研究资料整合报告》突出核心发现、解释之间的分歧、选定的机制及论点修订；正文压缩，阅读记录与核验细节放资料索引；重做时保留旧版及仍成立的成果。
- 研究报告是写作的弹药库，不是写作的骨架：成稿只用其中一小部分，这是正常的。

### 大纲

- 以取舍为主。先定全片要回答的一个问题和一条论证与叙事线，每章只服务这条线，章与章是推进关系；材料按线的需要调用，未选用的不必罗列。
- 包含：主线问题、情绪走向、三到五个备选标题、多个备选开场（各附试写）、每章论证什么／怎么论证／用什么材料／如何推到下一步、结尾方向和主要取舍；另列篇幅预算（旁白约 250 字／分钟）。
- 大纲是写作指南，不是合同。写到某章发现大纲那段立不住（例：先立劳动说再推倒，像上课），直接按更好的写法写，并说明改了什么。

## 二、写作

### 每章怎么写

- 写之前先通读 `自己的/` 范例全文，并以已定稿的开场和前几章为文风样板。
- 开篇明义：第一段就亮这一章要揭穿什么，不用回扣上一章来起头。
- 一章一个隐喻或一条递进线，每一拍从自己的材料起手；拍与拍之间靠论证递进，不写过渡句。章与章的转场交给题记卡的“咔哒”。
- 章节标题不剧透章内翻转；可以借材料里的现成说法（惠普原话“一笔糟糕的投资”、《资本论》“魔法妖术”）。每章一张题记卡，引文可以和标题互相呼应。
- 研究术语进正文前翻成人话；理论家点名控制在必要的几位，其余只讲内容。
- 跟踪篇幅：每章写完数一次旁白字数，对照大纲预算。

### 事实尺度

- 七分真三分假是正常的文案写法：修辞性概括、夸张、归纳不逐条较真，不在草稿里写批注，也不在对话里反复提示。
- 只避开会被抓的硬伤：引文原话、出处归属、具体数字、张冠李戴、术语误用。Agent 在自己写的句子里直接写对，不另外报告。
- 草稿末尾只设“素材来源”，记录稿中用到的图片、视频等素材出处；不写待核清单或论文式说明。

### 素材与画面占位

- 用户提供的截图、片段可以加工成可用素材（裁切、高亮、标注出处），存入 `assets/generated/`，原图另存不覆盖，在 `manifest.yaml` 登记。
- 稿中用【画面】或（可用素材）标出对应素材；飞书文档里显示为“暂时无法在飞书文档外展示此内容”的位置，同步回草稿时换回素材路径。

## 三、协作模式的轮次规矩

- **开场**逐句打磨：每句给多个候选并说明用词意图，用户删改后的版本即为定稿。
- **逐章循环**：Agent 做加法（细节、意象、笑点、论据、备选表达），用户做减法（删、选、定）。
- **用户贴回的版本就是新的真相。** 原样写入草稿，一个字不改；Agent 上一轮加的东西，用户版本里没有的，一律当作已删，不加回、不换个说法再来。
- **加法的格式**：用户原文在前，Agent 的内容用【加·类别】标出，写明接在哪一句后面；每处最多一主一备，并给一句推荐理由。每一轮都要是新内容。
- **按用户指定的焦点加**：用户说“专注笑点”“文采、衔接、动员”，这一轮就只做这些。
- **异议只说一次**，由用户决定。
- 一轮做完直接交付，不追问“要不要继续”。

## 四、全自主模式

### 开工

- 用户给出核心议题和独特切入点，并说明全自主，即授权本项目文案阶段的全部常规工作：联网检索、平台采集（知乎、B站评论与字幕）、阅读与下载研究资料、创建项目目录、写入各阶段文件，直到 `script.md`。不包括：下载正式制作素材、生成或渲染媒体、发布、推送到 GitHub。
- 开工先建 `decisions.md`，记录本期理解、预计篇幅和各阶段计划。

### 自己当用户

协作模式里用户承担的判断，全自主模式由 Agent 显式完成：

- **阶段关卡**：每个阶段结束时，在 `decisions.md` 写下选了什么、放弃了哪些备选、为什么。方向判断置信度低于约九成的决定要特别标出，供用户事后优先看。
- **自己做减法**：每章先按协作模式的方式写出“原文加备选”，再站在用户的立场删：删套话、边界说明、没长在逻辑上的笑点、重复回扣；每处备选只留一个。删改后的版本才写入草稿。
- **用用户的眼光验收**：每章对照 `brand/voice.md` 的招式和正反例检查一遍；全稿写完后做整体润色和机械检查（见下文）。
- **轮数上限**：每章自改不超过两轮，开场不超过三轮，防止原地打磨。

### 停止条件

只有以下情况停下来问用户，其余自行推进：

- 需要用户提供凭据，或遇到必须本人完成的登录、验证码。
- 选题触及用户信息中没有表态、而 Agent 判断会显著影响账号立场的问题。
- 研究推翻了用户给的核心议题或切入点，项目需要换方向。

### 交付

- 完成后给一份简短收尾说明：全片要回答的问题、核心论点、标题、各章一句话、最值得用户重点看的三处（通常是置信度最低的决定和最冒险的笑点），以及 `decisions.md` 的位置。
- 用户随后可以按协作模式继续删改；删改结果是校准全自主模式的最好材料，定稿后与 Agent 原稿对照，把新发现的偏好补进 `brand/voice.md`。

## 五、收尾两步

- **整体润色**：全稿定了以后单独做一遍，只动断句、措辞、衔接，不删内容、不加新论点，另存为润色稿并附改动清单。不要把用户要的修辞删素。
- **机械检查**：数重复词和重复片段、编辑残留（叠在一起的两个版本、重复字）、同词扎堆、术语误用。重复是主线回扣的不用动。之后整理为 `script.md`：旁白、屏幕文字、素材与镜头意图。
- 每个完成的项目，把 `script.md` 的旁白复制一份到 `assets/references/style-examples/自己的/`，作为后续项目的文风范例。
